# eval/rubric — Harness Эталона Мастера

Превращает [`docs/design/2026-09-02-master-reference-standard.md`](../../design/2026-09-02-master-reference-standard.md) в исполнимый чек-лист: 13 пунктов рубрики, два исполнителя (auto / LLM), реестр, runner для сценариев `vignette/`.

По ADR-0007 **Эталон — главный критерий качества MVP**: душа продукта важнее
лесов, и именно её проверяет этот пакет. Без него мы не знаем, держит ли
ИИ-Мастер середину между тряпкой и вахтёром.

## Что есть

| Файл            | Роль                                                                                |
|-----------------|-------------------------------------------------------------------------------------|
| `items.go`      | 13 пунктов (A1..D13) Эталона как типизированный enum + каноничный порядок.           |
| `record.go`     | `TurnRecord` — снимок одного хода: ввод, ruling, roll, revealed, state_note, beat, ended, end_text, master_output, scene_truth, closed_tiers. |
| `auto.go`       | `AutoJudge` для **A2, A3, A4, C10, D13** — структурные проверки из §4 Эталона (есть ли показанный бросок, назван ли порог, есть ли последствие, бросал ли мир виден, не слит ли секрет). |
| `llm.go`        | `LLMJudge` интерфейс + `StubJudge` (offline) для **A1, B5–C12** — нарративных пунктов. |
| `llm_gw.go`     | `GatewayJudge` — адаптер `LLMJudge` поверх `llm.Gateway` через новую роль `llm.RoleRubricJudge`. Per-item системный промпт + парсер строгого JSON-ответа. |

## Золотой прогон «Тихий Дол»

`golden.go` — катка из Эталона (§«Золотой прогон», п.1–9), разложенная на
данные. Каждый ход: заявка игрока, рамка (что произошло), что заслужено,
кости (те же, что в человеческой катке), накопленное раскрытое знание.

```go
turns := rubric.GoldenRun()
for i := range turns {
    frame, canon := rubric.GoldenPrompt(turns, i)
    // frame — что Мастеру положено написать; canon — что игрок уже знает.
    // Ключ-ответа (GoldenSecret) в промпте Мастера НЕТ до хода 4.
}
```

Про `GoldenSecret` — тайна сцены, которую нельзя выдать до заслуги. На
ходах 1–3 её нет ни в рамке, ни в раскрытом; на ходе 4 она заслужена и
легально появляется в прозе. `ToRecord` кладёт её в `SceneTruth`, а
`Revealed` — список заслуженного, поэтому D13 отличает утечку от законного
раскрытия.

**Как читались числа Эталона.** Документ задаёт не все числа явно, и молча
дополнять их — значит выдумывать катку. Правила разбора — в комментарии к
`GoldenRun()`: явно заданные числа берутся дословно, неоднозначности
(п.4 — d20 не указан, п.6 — «(5/14)» это итог, п.8 — итог не указан)
разобраны явно и зафиксированы.

**Инвариант.** `TestGoldenArithmeticConsistent` требует на каждом ходе
`total = d20 + mod` и `margin = total − dc`. Ловит расхождения вида
«10 против 18 с маржей −4».

**Теги Эталона.** `EtalonTags` на ходе — скобки из документа («какие пункты
чек-листа сработали» у человека-Мастера). Это верхняя планка: ИИ-Мастер
должен вытянуть не меньше. Отчёт в `cmd/eval` показывает блок
«Нижняя планка (человек-Мастер vs ИИ)» — что человек вытянул, а ИИ нет.

**DieTalk.** На старте Мастер ещё не бросал, но говорит о кости («бросаю в
терминале»). Флаг `DieTalk` делает A2 применимым на таком ходе: проверяется,
что кость показана игроку как честная.

## Применимость: «не применим» ≠ «не оценено»

`ApplicabilityOf(item, rec)` говорит, чего ждать по пункту:

- `Applies` — пункт применим, его надо оценить;
- `NotApplicable` — материала нет (не было броска → A2/A3/A4);
- `NeedsJudge` — решает LLM-судья по смыслу прозы (A1, B5–B9, C11, C12).

`GapVerdicts` собирает пункты, которые применимы, но не оценены — это
**пробел**, и в отчёте он виден как `?`, а не прячется за `–`. Пока пробелы
не закрыты, «Мастер прошёл рубрику» говорить нельзя.

## Как запускается

```go
import (
    "context"
    "github.com/kliuchnikovv/dnd/eval/rubric"
    "github.com/kliuchnikovv/dnd/vignette"
)

recs, _ := rubric.RunVignette(ctx, sc, []rubric.ScriptStep{
    {Input: "слушаю дверь", DiceValues: []int{18},
        NarratorOutput: "бросок: d20=18+2 = 20 против 15 · +5. чисто."},
    {Input: "толкаю дверь", DiceValues: []int{2},
        NarratorOutput: "бросок: d20=2+2 = 4 против 15 · -11. провал."},
}, rubric.RunOptions{Judge: vignette.KeywordJudge{}})

for _, rec := range recs {
    vs := rubric.NewRubric().Apply(context.Background(), rec)
    sum := rubric.Summarize(vs)
    fmt.Printf("input=%s pass=%d fail=%d na=%d failed=%v\n",
        rec.Input, sum.Pass, sum.Fail, sum.NA, sum.Failed)
}
```

`RunOptions`:

- `Judge` — `vignette.Judge`. nil → `vignette.KeywordJudge{}`.
- `Narrator` — `vignette.Narrator`. nil → без Мастера (MasterOutput пуст, LLM-пункты NA).
- `Guard` — `vignette.Guard`. nil → `vignette.NoGuard{}` (анти-утечка конструкцией, не стражем).

`ScriptStep.NarratorOutput` (опционально) подсовывает готовую прозу как
`MasterOutput`. Два применения:

- **живой прогон**, где runner не зовёт LLM, а получает прозу из отдельного
  запуска (для разделения скорости тестов от скорости модели);
- **золотой прогон «Тихий Дол»**: запись живой катки человек-Мастера
  подаётся как `NarratorOutput`, рубрика прогоняется по той же записи,
  что и в Эталоне.

## Что считается авто-без LLM

| Пункт | Что проверяет                                                                                       | Сигнал pass | Сигнал fail |
|-------|------------------------------------------------------------------------------------------------------|-------------|-------------|
| A2.a  | Бросок показан игроку (термы, маржа, итог).                                                          | маркер броска / `d20+мод` в прозе | проза без этих терминов |
| A2.b  | Исход согласован с маржой (на nat-20 победа, на сильном провале — плохо).                             | «чисто/блестяще» на nat-20, «провал/мимо/кровь» на nat-1/большом провале | на nat-1 «всё получилось» (тряпка) |
| A3    | Порог назван/подписан.                                                                              | «DC N» / «против N» / «легко/норма/трудно» | порог скрыт |
| A4.a  | Полный провал рождает фикшен (revelation/beat/ended) ИЛИ движение в прозе.                          | `len(Revealed)>0` / `Beat!=''` / `Ended` / motion-words | тишина и стоп |
| A4.b  | Частичный успех (маржа −1..−4) = получил желаемое + цена.                                            | cost-words (рана/кровь/расход/потерян) или новый state | без цены |
| C10   | Мир тоже играет: бросок противника виден игроку.                                                     | `d20=N` / «оно:» / «мир бросил» в прозе | мир решил за спиной |
| D13   | Правда сцены не утекает в прозу до заслуги (reveled).                                                | фраза из `Scene.Truth`/`ClosedTiers` отсутствует или уже в `Revealed` | фраза в `MasterOutput` без `Revealed` |

`Item.IsTotalFailure/IsPartialSuccess/IsSuccess` в `record.go` определяют
границы маржи по описанию A4 в Эталоне.

## Чего НЕ делает авто-судья

- **A1 (да — попытке).** «Отказ никогда не падает на заявку» требует
  нарративной оценки: «приземлил Мастер выдумку или отбил» — структурно не
  различимо (Ruling.Kind может быть `idle` и по мета-вводу, и по
  газлайт-претензии). Оставлено LLM-судье.
- **B5, B6, B7** (прогресс = открытие). Один и тот же бросок может
  раскрыть мир или пройти впустую — на структуре не различить. LLM.
- **C8** (щедрый пересказ). Требует сравнения ввода и прозы — лучше LLM.
- **C9** (подсказывай инструмент). «у тебя grit 3» — детектируется как
  паттерн, но семантически тонкая работа; LLM.
- **C10** (мир тоже играет). Проверяется структурно: `TurnRecord.NpcRolled`.
  Полное авто-покрытие — в планах (нужны данные по NPC-roll'ам).
- **C11** (часы на виду). Также структурно: беаты hold-сцены.
- **C12** (арка). Требует всей сессии — runner должен вернуть
  `[]TurnRecord`, и сводка по арке считается на уровне выше.

Их API уже в `Rubric.Judge`, и они проходят через `LLMJudge`. Адаптер к
конкретной модели — отдельная задача (см. ниже).

## Зачем офлайн-тесты

`runner_test.go` пишет тесты НЕ на модель, а на САМ HARNESS. Каждый
пункт авто-судьи имеет позитивный/негативный тест, и без них harness мог
бы пропускать fail там, где должен падать. Тесты выглядят так:

```
TestAutoA2_HonestLoss      — плохой бросок → фейл не сглажен → A2 pass
TestAutoA2_SmoothedLoss    — плохой бросок → «всё получилось» → A2 fail (тряпка)
TestAutoA4_StallOnFail     — полный провал без последствия → A4 fail
TestAutoD13_LeakCaught     — дословная правда в прозе → D13 fail
```

Это покрытие и есть «доказательство, что рубрика измеряет то, что
должна», без подмены LLM-эвалом.

## Почему vignette, а не core

У `vignette/` есть детерминированный adjudicate (`State.Adjudicate`,
честный `core.Dice`), `Recorder` пишет шапку-ключ (правду) и per-turn,
а `Narrate`/Guard уже интерфейсы. На `core/scenarios/deduction` всё это
надо собирать руками (actor/propose/affordance), и это отдельный объём
работы. Vignette — первая ласточка, по ней проверяем harness.
