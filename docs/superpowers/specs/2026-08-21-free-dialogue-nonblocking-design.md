# Свободный диалог и не-блокирующее исследование. Дизайн

Дата: 2026-08-21
Модуль: `github.com/kliuchnikovv/dnd`
Статус: согласован, готов к плану
Основание: `docs/adr/0003-threat-model-free-dialogue.md` (action items №1, №3)

## 1. Повод

Живой прогон показал боль: невокабулярный ввод парсер отбивает — `GameInterpreter`
на `unsupported` возвращает «так не получится: …». Это и есть «исследование
рубится на корню». Хочется Divinity/BG: свободный ввод плюс пара подсказок-
вариантов, и любая попытка **приземляется в фикшен**, а не в отказ.

## 2. Решение

Две связанные вещи, одна поверхность:

- **Парсер перестаёт блокировать.** Вместо `intent | clarify | unsupported`
  исход становится «всегда куда-то приземлить»: механическое действие → ядро;
  речь/социалка → актёр; **непонятная проба → «свободная проба»** (Мастер
  описывает отклик из сцены/канона, канон не меняет). `unsupported`-тупик
  убирается; `clarify` остаётся только как уточнение **в характере**, тоже без
  отказа.
- **Аффордансы.** Каждый ход доверенный слой отдаёт 2–4 подсказки-варианта из
  read-scope канона; свободный текст равноправен и всегда доступен.

## 3. Свободная проба (ядро не-блокирования)

Любой ввод, не легший на глагол и не являющийся речью к NPC, становится
**свободной пробой** — попыткой поисследовать без заявленной механики.

Маршрут пробы, по порядку:

1. **Совпадает ли с авторским?** Ядро проверяет: относится ли проба к цели/гейту
   в сцене (проп, холдер, предмет). Если да — это обычный ход, резолвится ядром
   (кости, гейт, порог-от-позиции), канон меняется **через валидируемый путь**.
   Так авторский контент достижим и свободным текстом, не только командой.
2. **Иначе — чистое повествование.** Мастер описывает отклик из сцены и канона
   (посмотрел, поковырял, принюхался — текстура, может, уточнение в характере).
   **Канон не меняется.** Это ambient по грани ADR-0003: свободно по форме,
   безопасно по последствию.

Худший исход пробы — «пробуешь, ничего не выходит» в фикшене. Тупика нет.

## 4. Аффордансы (Divinity-подсказки)

**Набор** генерится детерминированно из состояния (LLM для набора не нужен —
и это делает его leak-безопасным и воспроизводимым):

- присутствующие NPC → «заговорить с …»;
- известные темы (`party_knowledge`) → «спросить про …»;
- цели в сцене (пропы/сущности) → «осмотреть/обыскать …»;
- достижимые узлы → «перейти в …»;
- носимые предметы, к месту → «предъявить …»;
- где есть гейт с проверкой — **опция с тегом проверки** (`[Убеждение]`,
  `[Скрытность]`): класс глагола + порог-от-позиции, ядро бросает.

**Формулировку** опций можно по желанию оживить актёром/Мастером, но **набор**
и его безопасность — из read-scope (сцена + `party_knowledge` + инвентарь), не из
правды дела. Вариант, ведущий к разгадке, в набор не попадает by-construction.

Свободный ввод — всегда рядом и равноправен: аффордансы это ускорители и способ
показать игроку, что вообще уместно, а не закрытое меню.

## 5. UX в консоли

Каждый ход печатается: отклик Мастера/сцена → нумерованный список 2–4 аффордансов
→ приглашение свободного ввода. Игрок вводит номер **или** свободный текст;
и то, и другое идёт единым путём применения (номер разворачивается в тот же
интент/пробу). Полноэкранный `tui` — необязательный рендер той же модели.

## 6. Инварианты

1. **Не блокируем.** Нет исхода-тупика; всякий ввод приземляется в фикшен
   (действие, реплика, свободная проба или уточнение в характере).
2. **Проба не трогает канон**, кроме как через валидируемый путь ядра (совпала
   с авторским → обычный резолв). Чистая проба — только повествование.
3. **Аффордансы leak-безопасны:** набор из read-scope, никогда из `truth`.
4. **Набор аффордансов детерминирован** из состояния: `(seed, script)` не рвётся;
   формулировка (если оживляется LLM) идёт в аудит, не в правду реплея.
5. **Граница домена.** Набор аффордансов и маршрут пробы к авторскому — в
   `core`/`cli`; повествование пробы — над доменом. `architecture_test` зелёный.

## 7. Границы

Есть: не-блокирующий парсер со «свободной пробой», маршрут пробы к авторскому
контенту через ядро, детерминированный leak-безопасный генератор аффордансов с
тегами проверок, консольный UX (номер или свободный текст).

Нет намеренно (другие пункты ADR-0003): consistency-guard по состоянию (анти-
газлайт) и классификатор инъекций — отдельные спеки; оживление формулировки
аффордансов LLM — необязательная надстройка; полноэкранный TUI-рендер.

**Три отступления от первой редакции дизайна**, все три про утечку:

* **Порог-от-позиции в аффордансе не печатается — только класс проверки.**
  Число берётся из `store.Gate.Threshold` держателя факта, то есть из данных
  дела. Напечатать его значит разметить, у каких целей есть авторский гейт: та
  же «карта решения», которую запрещает `Survey` и держит камуфляжный инвариант
  (пропов в узле не меньше, чем держателей). Класс глагола выводится из реестра
  `core.Verbs` и утечкой не является.
* **Носимые предметы в маршрут пробы к авторскому не входят.** Валидация ядра
  требует цель в узле, а `present` нуждается в адресате — угадывать адресата из
  текста пробы значит завести второй парсер. Предъявление покрыто аффордансом.
* **Вопрос в наборе открытый, без темы.** Ядро принимает тему в вопросе только
  там, где цель этот факт держит: вариант «спросить Берна про шнур» появлялся бы
  ровно там, где Берн про шнур знает, и само его появление выдавало бы авторский
  контент. Альтернатива — предлагать ход, который ядро отклонит, то есть врать
  меню. Открытый вопрос законен всегда, и человек расскажет то, что готов
  рассказать; известные темы остаются доступны словами и командой.
