# D&D-приключение как второй трек. Дизайн

Дата: 2026-09-01
Модуль: `github.com/kliuchnikovv/dnd`
Статус: согласован, готов к плану
Основание: ADR-0006 (две оси пластичности), ADR-0001 (доверенное ядро, шов `RuleSystem`), ADR-0004 (turn-view, дескрипторная презентация)

## 1. Повод и границы

Существующий движок — «Порог × детектив»: одна пара «правило × сценарий», построенная богато и первой. Задача — **параллельный трек**: второй `RuleSystem` (лёгкое подмножество D&D 5e) и второй сценарный архетип (`adventure`, dungeon/hex-crawl), играющиеся на том же ядре с первым игровым кейсом «Ночной маяк».

Сознательно **нарушаем action item №5 ADR-0006** («не строить вторую реализацию, пока швы не отлажены»): именно эта работа и есть тест швов. За решением стоит другая цель — не «удвоить контент», а понять, что даст D&D-механика на движке, где сила уже показана в свободном разговоре с NPC. Ответ, ради которого затевается эксперимент: **живёт ли исследование мира и свободный диалог, когда рядом сидит настоящая боевая система**.

**Что в границах:**

- Новый шов `core.Scenario`, за него уводится нынешняя детективная логика (`accuse`, `corroboration`, `hunch`, панель казбука).
- Новый пакет `rules/dnd5e/` — упрощённое подмножество 5e: d20-чеки, спасброски, атаки, HP, инициатива, три условия.
- Новый пакет `core/scenarios/adventure/` — цель/победа/поражение/панель/AI монстров для solo-приключения.
- Минимальные добавки в `core`: HP/AC/условия на сущности, `Encounter` (инициативная лента + флаги действий).
- Первый кейс `cases/lighthouse/case.json` — «Ночной маяк», 6 узлов, три способа взаимодействия (разговор/навык/бой).

**Что вне границ:**

- Заклинания, слоты, cantrips, классы, левелап, feats.
- Партия и NPC-союзники. Solo-герой, как сейчас.
- Encounter builder (авто-подбор монстров по CR/XP). Автор кладёт встречи руками.
- Reactions, attacks of opportunity, area damage.
- Правки клиента поверх минимального. Rich-UI карты и боевого журнала — задача второй фазы.

## 2. Ключевые решения

**2.1. Параллельный трек, не замена.** «Порог» + детектив остаются в проде, тесты harbour и forte_merlo обязаны быть зелёными на каждом шаге. Второй трек добавляется через выбор в `case.json` (`scenario:` и `rules:`), fallback — на существующее поведение.

**2.2. Сценарный шов вводится сразу, не после эксперимента.** ADR-0006 говорит «увести детектив за шов», и это делаем в фазе 1. Без шва второй архетип пришлось бы имплементировать «параллельно живущей веткой» с большим долгом. Со швом обе реализации — first-class.

**2.3. Расширяемость до полной 5e — обязательное свойство.** Лист хранит ability scores (не модификаторы), `Weapon.Damage` — полный dice-грамматик, `Verbs` расширяются через `Scenario.ExtraVerbs()`, resolve — switch по классу. Полный 5e (заклинания, классы, условия, реакции) достраивается **добавлением, не переписыванием**. Точки роста перечислены в §5.

**2.4. Свобода разговора — на равных с механикой.** Adventure-кейс проектируется так, чтобы NPC с большой карточкой (голос, быт, `talks_about`, `open_threads`) можно было свободно расспрашивать, и это было бы столь же весомой частью игры, как бой и навык. Талан-призрак на лестнице маяка — фокусный NPC теста этой стороны.

## 3. Сценарный шов

### 3.1. Интерфейс

```go
package core

type ScenarioKind string // "deduction" | "adventure"

type Scenario interface {
    Kind() ScenarioKind

    // ExtraVerbs — глаголы, которых нет в общем реестре. Общие глаголы
    // (talk_to, examine, question, ask_about, search, move_zone, take, drop,
    // use, present) остаются в едином core.Verbs.
    ExtraVerbs() []VerbDef

    // Victory/Defeat — одна точка правды на архетип. Читают состояние
    // игры и авторские условия из case.json; ядро не знает конкретики.
    Victory(g *Game) (won bool, why string)
    Defeat(g *Game) (lost bool, why string)

    // Panel — дескриптор рабочей панели клиента. Форма — общая
    // (Panel/Section/Slot из ADR-0006 ред.2), содержимое — от сценария.
    Panel(g *Game) Panel

    // NPCTurn — единственный крючок сценария в такт игры. Вызывается ядром
    // после того, как инициативная лента продвинулась на NPC.
    // deduction возвращает nil (у него NPC ходов не бывает).
    NPCTurn(g *Game, id EntityID) (Intent, bool)
}
```

### 3.2. Выбор сценария при загрузке

`cases/*/case.json` получает опциональное поле `scenario:` (`"deduction"` | `"adventure"`). Отсутствие поля читается как `"deduction"` — обратная совместимость. `rules:` — аналогично: `"threshold"` (default) | `"dnd5e"`. `cases.Load` подставляет соответствующие реализации в `Game.Scenario` и `Game.Rules`.

### 3.3. Перенос детектива за шов

Пакет `core/scenarios/deduction/`:
- `hunch.go`, `accusation/`, часть `knowledge.go` (corroboration, has-fact-gates) перемещаются из `core/`.
- Публичное API того, что читает CLI и клиент (например, `HunchOptions`, `AccuseForm`), сохраняется по путям импорта через re-export или переезжает — решается в плане.
- Тесты перемещаются вместе с кодом.

**Гарантия:** после переноса поведение harbour и forte_merlo — бит-в-бит то же. Тестовые прогоны e2e зелёные.

### 3.4. Что НЕ входит в шов

Граф фактов (`Facts`, `FactID`, `Knowledge`, `TopicBank`), досье, гейты выдачи фактов — **остаются в `core`**. Это утилиты знания сущностей, а не archetype-specific. Adventure-кейс тоже сможет ими пользоваться (например, «карта известных проходов подземелья»). Убрать их за deduction было бы искусственным.

## 4. Правила `rules/dnd5e/`

### 4.1. Лист персонажа

```go
type Sheet struct {
    // Ability scores 8..20. Модификатор = (score-10)/2.
    Str, Dex, Con, Int, Wis, Cha int

    // Фиксированный +2 для уровня 1-4. Уровень не храним — solo-приключение
    // это одно погружение. При переходе к кампании: level + prof-таблица.
    Prof int

    // Списки навыков, спасбросков — proficiency-биты по имени. Расширяемо.
    Skills []string  // "athletics", "stealth", "perception", ...
    Saves  []string  // "str", "dex", "con", "int", "wis", "cha"

    MaxHP int
    AC    int
    Speed int

    Weapons []Weapon

    // Точки роста (пока не читаем, поле опциональное в JSON):
    // Classes []ClassLevel, Features []FeatureID, Spellbook, Slots.
}

type Weapon struct {
    Name   string
    Reach  string // "melee" | "ranged"
    Attack string // "str" | "dex"
    Damage string // "1d8+str" | "1d6+dex" | "1d10 versatile 1d12"
}
```

Хранится в `case.json → character.sheet` как `json.RawMessage`. Ядро листа не читает.

### 4.2. Резолв

```go
func (s *System) Resolve(in Intent, view SceneView, d Dice) Resolution {
    def := Verbs[in.Verb]
    if !def.Rolls { return Resolution{Class: OutcomeSuccess} }
    switch def.Class {
    case ClassAttack: return s.resolveAttack(in, view, d)
    case ClassSave:   return s.resolveSave(in, view, d)
    default:          return s.resolveCheck(in, view, d)
    }
}
```

- **Check:** `d20 + ability + prof(if_proficient) vs DC`. DC приходит из `case.json` (`checks:` секция на глагол/цель) или из `DifficultyFor(in, view)` по тегам обстановки.
- **Attack:** `d20 + ability + prof vs targetAC`. Попал — damage roll. `d20 = 20` — крит, дайсы урона удваиваются.
- **Save:** `d20 + ability + prof(if_save) vs DC`. Сохранил — эффекта нет; провалил — вешает мутацию (условие/HP-delta).

**Advantage/disadvantage** — две кости, выше/ниже. Источники ситуативных модификаторов: скрытность → advantage на первую атаку, ослеплён → disadvantage. Собираются в `Situational(in, view)`, как в `threshold`.

### 4.3. Глаголы D&D

Возвращаются из `adventure.Scenario.ExtraVerbs()`, читаются `dnd5e`:

| Verb | Class | Что считает |
|---|---|---|
| `attack` | Attack | d20+mod+prof vs AC → damage |
| `hide` | Check | Dex(stealth) vs пассивная Perception врагов |
| `sneak` | Move | движение + Dex(stealth) |
| `disarm_trap` | Check | Dex(thieves-tools) vs DC ловушки |
| `detect_trap` | Check | Wis(perception) vs DC ловушки |
| `pick_lock` | Check | Dex(thieves-tools) vs DC замка |
| `flee` | Move | Dex vs скорость преследователя |
| `rest_short` | Recover | восстановление HP через Hit Dice |
| `rest_long` | Recover | полный HP + сброс условий |

`examine`, `search` — общие глаголы, `dnd5e.Resolve` привязывает им Wis(perception) или Int(investigation) по контексту.

### 4.4. Пакетная структура

```
rules/dnd5e/
    sheet.go       // Sheet, ParseSheet, модификаторы
    dice.go        // парсер "NdM+mod" с ability-подстановкой, крит
    skills.go      // map skill → ability
    check.go       // resolveCheck
    attack.go      // resolveAttack + damage
    save.go        // resolveSave
    initiative.go  // Dex-based расчёт, tie-breaker rng
    verbs.go       // definitions returned to Scenario.ExtraVerbs()
    resolve.go     // System и диспетчер
```

Каждый файл — одна ответственность. Модульные тесты — 30-40 штук: advantage, крит, save проваленный/успешный, каждая ветка check, парсинг «1d10 versatile».

## 5. Точки роста до полной 5e

Проектные решения, обеспечивающие «добавить, не переписывать»:

| Что | Как заложено |
|---|---|
| Заклинания и слоты | `Sheet.Spellbook`, `Sheet.Slots` — опциональные JSON-поля. `ClassSpell` — одна ветка switch в `resolve.go`. Verb `cast_spell` — добавляется через `ExtraVerbs`. |
| Классы, левелап | `Classes []ClassLevel` в листе. Prof-таблица по уровню — файл `rules/dnd5e/progression.go`. |
| Feats, features | `Features []FeatureID` в листе. Обработчики — под ключом в `dnd5e/features/`. |
| Reactions, held actions | Поле `Reaction bool` в `Encounter.Actions`. Триггеры — hook `Scenario.OnEvent`. Не сейчас, шов заложен. |
| Все 15 условий | Условия — теги на сущности, эффект — таблица в `dnd5e/conditions.go`. Первые три: `prone`, `poisoned`, `restrained`. |
| Многоцелевые/AOE атаки | `Intent.Args.Targets []EntityID` (не `Target`). Резолв атакует по каждому. Мутация `MutHPDelta` уже принимает одну цель — цикл. |
| Death saves, temp HP | `Entity.TempHP`, `Entity.DeathSaves` — опциональные поля, добавляются при первой надобности. |

Точки, где **потребуется небольшая правка**, а не расширение:

- `Encounter.Order` — сейчас `[]EntityID`; при readied action появятся «вставки в середине». Расширение до `type InitEntry struct { ID EntityID; Priority int }`.
- Клиентская `Panel` — расширение секций под слоты/заклинания. Форма остаётся, содержимое дописывается.

## 6. Добавки в `core`

### 6.1. Поля на сущности

```go
type Entity struct {
    ...
    HP     int // 0 — не участвует в HP-механике (детективные NPC)
    MaxHP  int
    AC     int
}
```

Опциональные. `MaxHP == 0` — «не считается» флаг: детективные сущности не трогают.

### 6.2. Encounter

```go
type Encounter struct {
    Order   []EntityID
    Turn    int          // индекс в Order
    Round   int
    Actions ActionState  // action/bonus использованы?
}

type ActionState struct {
    Action, Bonus bool // false — доступно
}

// В Game:
Encounter *Encounter // nil — не в бою
```

### 6.3. Мутации

- `MutHPDelta{Target EntityID, Delta int}` — урон/лечение. HP≤0 → мертво, из `Order` вычёркивается на следующий продвиг ленты.
- `MutSetCondition{Target EntityID, Condition string, TurnsLeft int}` — вешает/снимает условие.
- `MutEncounterStart{Order []EntityID}` — вход в бой.
- `MutEncounterEnd` — выход из боя (все враги мертвы или сбежали).
- `MutAdvanceInitiative` — конец действия сущности, ход к следующей.

### 6.4. Хуки применения хода

В `Game.Apply` перед резолвом:
- Если `Encounter != nil` и текущий `Turn` не игрок — отказ «не твой ход».

После резолва:
- Если `Encounter != nil` — `MutAdvanceInitiative`. Пока следующий по ленте — NPC, ядро в цикле вызывает `Scenario.NPCTurn`, применяет полученный интент и продвигает ленту. Возврат управления игроку — когда `Turn` указывает на игрока. Гарантия отсутствия зацикливания: `Turn` монотонно движется вперёд, за один круг ленты его продвижение равно длине `Order`; безопасность формально закрепляется счётчиком в цикле, равным `len(Order)+1`.

### 6.5. `NPCTurn` для adventure

Простейший AI: если рядом враг — `attack` на ближайшего в reach. Если нет — `move_zone` к ближайшему врагу. Одна атака или одно движение за ход. AI живёт в `core/scenarios/adventure/ai.go`.

## 7. Кейс «Ночной маяк»

### 7.1. Сеттинг

Маяк на скалистом мысу над бухтой Гавани (тот же мир, что «Пристань»). Свет погас три ночи назад — суда бьются об рифы. Смотритель Талан пропал. Гильдия платит награду за возвращённый огонь. Мыс: тропа, руины часовни, ворота маяка, винтовая лестница, комната фонаря. Кристалл-сердце из линзы украли контрабандисты с северной бухты.

**Почему этот сеттинг:** переиспользует сеттинг-библию «Пристани» (море, гильдия, климат); компактный; вертикальная структура; даёт три типа взаимодействия и один сильный разговорный NPC.

### 7.2. Герой

**Кей** — контрабандист-полукровка, знает бухту, ушёл в дело за деньгами гильдии. `Str 12, Dex 16, Con 13, Int 11, Wis 12, Cha 10`. Proficient: dex-save, stealth, thieves-tools, perception. Оружие: короткий меч (1d6+dex), метательные ножи (1d4+dex, ranged). MaxHP 12, AC 14, Speed 30.

Не воин, не маг — ловкий и осторожный. Отражает философию кейса: стелс и разговор важнее лобового боя.

### 7.3. Узлы

1. **n_shore** — рыбацкий причал под скалой. Старт и точка возврата (победа). NPC-рыбак, краткий диалог, лоурный контекст, запасной ключ от ворот.
2. **n_path** — тропа, разрушенный мост. Dex-save DC 12; провал → 1d6 урона и обратно.
3. **n_ruins** — руины часовни. 2-3 гарпёныша (HP 4, +2 to hit, 1d4). Первый бой.
4. **n_gate** — ворота маяка. Три пути: pick_lock DC 15, ключ от рыбака (по разговору), athletics DC 18.
5. **n_stairs** — винтовая лестница. **Талан-призрак** — большая карточка (voice, life, talks_about про смотрителей мыса, огонь, жену, старые времена). Ловушка выше — падающая балка, detect_trap Wis DC 14; провал → Dex-save DC 13, 2d6.
6. **n_lantern** — комната фонаря. **Вор** (HP 20, AC 13, короткий меч). Финал: драка ИЛИ уговор на сделку (если Кей узнал ключевое от Талана).

### 7.4. Победа/поражение

- Победа: `victory: {type: "return_with", item: "i_lightcrystal", node: "n_shore"}`.
- Поражение: HP≤0 без hit dice.

### 7.5. Что кейс проверяет

1. **Правила D&D работают вживую.** Два боя (гарпёныши, вор) — минимум под initiative/action/damage.
2. **Свободный разговор оживает.** Талан — большая карточка. Проверяем, держится ли граница «правды дела» (кто украл, где кристалл) при свободной прозе.
3. **Сценарный шов держит.** «Пристань» (deduction) и «Маяк» (adventure) играются параллельно, детектив не сломан.

## 8. Клиент и turn-view

Дескрипторная презентация (ADR-0006 ред.2, ADR-0004). `Panel(g)` для adventure:

- **Section «Здоровье»** — HP/MaxHP, статус-бар; условия (chip'ы).
- **Section «Карта»** — известные узлы, доступные направления.
- **Section «Инвентарь»** — предметы, экипировка.
- **Section «Инициатива»** — виден только в бою: порядок ходов, чей ход, action/bonus состояние.

Клиент рисует по дескриптору, конкретных полей не знает. Детективный казбук — отдельная реализация панели, adventure не влияет.

## 9. Тесты и гейты миграции

Каждая фаза (см. §10) имеет **гейт**: набор тестов, которые обязаны быть зелёными до перехода на следующую.

- **После фазы 1:** e2e харбур и forte_merlo играются идентично; тест «архетип deduction загружается по умолчанию, без правки JSON».
- **После фазы 2:** харбур и forte_merlo не заметили изменений (Encounter nil, HP не читается).
- **После фазы 3:** unit-тесты `rules/dnd5e` (30-40 штук) зелёные.
- **После фазы 4:** mini-adventure (2 узла, 1 монстр) проходится e2e; детектив не сломан.
- **После фазы 5:** оба кейса играются в клиенте.
- **После фазы 6:** «Ночной маяк» проходится, Талан говорит живо, свободный разговор не пробивает границу дела; e2e-тест этого прогона.

Гарантия портируемости: **тест агностичности презентации** (action item №4 ADR-0006) — в панели нет захардкоженных меток правила/сценария; проверяется как `architecture_test`.

## 10. План работ

| Фаза | Содержание | Оценка |
|---|---|---|
| 1 | Сценарный шов; перенос детектива за него; регрессия | 2-3 дня |
| 2 | HP/AC/Encounter/мутации в `core`; хуки Apply; deduction возвращает nil на всё | 2 дня |
| 3 | `rules/dnd5e/` — sheet, dice, resolve (check/attack/save), initiative, verbs; unit-тесты | 3-4 дня |
| 4 | `scenarios/adventure/` — Victory/Defeat/Panel/NPCTurn; mini-кейс интеграционный | 2 дня |
| 5 | Клиент: рендер `Panel` для adventure; ручной прогон mini-кейса | 1-2 дня |
| 6 | «Ночной маяк» — авторинг контента (JSON) | 2-3 дня |
| 7 | Обкатка, prompt-тюнинг реплик под adventure, метрики | плавно |

**Итог:** ~2 недели чистой работы, реально 2.5-3 с сюрпризами.

**Точка отката:** каждая фаза — своя мерж-точка. Фазы 1-2 почти бесплатны для отката (никто не менял поведения). С фазы 3 откат дороже, но `rules/dnd5e/` изолирован от детектива.

## 11. Что осознанно оставлено «на потом»

- **Encounter builder.** Автогенерация встреч по CR/XP-бюджету. Пока автор кладёт руками.
- **Классы, левелап, экспа.** Solo-приключение — одно погружение. Точки роста в §5.
- **Заклинания.** Первый заход обходится без них; шов расширяем.
- **NPC-союзники и партия.** Требуют модели `party` в ядре; сейчас — один Actor.
- **Rich map UI.** Клиент рисует список узлов + связи; графическая карта — позже.
- **Метрики D&D-стороны.** Как только пойдёт живой прогон — добавим отдельно.

Каждый пункт — расширение, не рефакторинг. Ничто из §5 не требует «выбросить и переделать».
