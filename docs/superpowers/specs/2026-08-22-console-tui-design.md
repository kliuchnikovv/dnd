# Консольный чат: полноэкранный режим. Дизайн

Дата: 2026-08-22
Модуль: `github.com/kliuchnikovv/dnd`
Статус: согласован в чате, готов к плану реализации
Предшественники: `2026-08-21-dialogue-actor-master-authority-design.md`

## 1. Зачем и что меняется

Игра стала разговором, а ввод остался тем, чем был на первом дне: `bufio.Scanner`
поверх stdin. Каретка по строке не ходит, опечатку в длинной фразе можно только
стереть целиком, повторить прошлый ввод нельзя, а кто именно говорит — игрок
определяет по тире в начале строки. Разговор длиной в сорок ходов так не ведут.

Меняется три вещи, и все три — над доменом:

1. **Ввод.** Полноэкранный режим с редактированием строки и историей ввода.
2. **Вывод.** Строки становятся событиями с автором, и потому у реплики есть
   метка говорящего, а у хода — разделитель.
3. **Отладка.** Дамп обмена с моделью переезжает с stderr в свою панель:
   в полноэкранном режиме stderr затирает экран.

Чего дизайн НЕ меняет: ядро, правила, дела, слой моделей. Ни одна строка ниже
не касается `core`, `rules`, `store`, `cases`, `dice` — граница домена остаётся
той же, и архитектурный тест это держит.

## 2. Инверсия цикла: `Feed` вместо `Run`

Сегодня циклом владеет `Session.Run()`: он сканирует ввод и печатает. Библиотека
полноэкранного режима владеть циклом обязана сама, поэтому сессия раскалывается
надвое.

- **`Session.Feed(line string) (done bool)`** — исполнить ОДИН ввод. Сюда
  переезжает всё, что сейчас происходит внутри тела цикла: `Parse`, `dispatch`,
  `interpret`, `applyIntent`, `speak`, проверка развязки. Логика не меняется,
  меняется её обёртка.
- **`Session.Run()`** остаётся и работает как раньше: тот же `bufio.Scanner`,
  в цикле зовущий `Feed`. Этим путём идут скрипты, пайпы и все существующие
  тесты — и идут **побайтово так же**, как сегодня.
- **TUI** — второй драйвер того же `Feed`.

Инвариант воспроизводимости по паре `(seed, script)` держится именно так: путь
без терминала не знает о существовании TUI и не меняется вовсе.

### 2.1. Обвинение как состояние, а не вложенный цикл

`Session.accuse()` сейчас печатает приглашение и читает ЧЕТЫРЕ строки подряд из
того же сканера — вложенный цикл ввода внутри хода. С `Feed` так нельзя: драйвер
отдаёт по одной строке и заблокироваться в ожидании следующей не может.

Обвинение становится маленьким автоматом на сессии: `Feed` заполняет один слот
и оставляет сессию в состоянии «жду токен для how». Следующий `Feed` заполняет
следующий. Приглашение уходит событием с пометкой `prompt`, и полноэкранный
режим показывает его подсказкой у строки ввода, а построчный — как сегодня,
`«who: a | b\n> »`.

Это не рефакторинг ради красоты: без него полноэкранный режим не сможет принять
обвинение вообще, а обвинение — единственный способ закончить дело.

## 3. Вывод как события

Сегодня вывод — байты в `io.Writer`, и узнать «кто это сказал» можно только
разбором напечатанного. Метка говорящего из разметки текста — это парсинг
собственного вывода, то есть та же ошибка, что чтение канона из прозы.

```go
type EventKind string

const (
    EventScene   EventKind = "scene"   // описание места
    EventProse   EventKind = "prose"   // проза Мастера об исходе
    EventSpeech  EventKind = "speech"  // прямая речь: NPC или игрок
    EventSystem  EventKind = "system"  // справка, факты, часы, состояние
    EventRefusal EventKind = "refusal" // «нельзя: …»
    EventPrompt  EventKind = "prompt"  // игру спросили: слот обвинения, уточнение
    EventNote    EventKind = "note"    // поломка надстройки: «Мастер промолчал»
)

type Event struct {
    Kind    EventKind
    Speaker string // «Берн, стражник» либо «Вы» — только у EventSpeech
    Text    string // ровно то, что печатается сегодня
}

type Sink interface{ Emit(Event) }
```

`Text` несёт УЖЕ отрендеренную строку или блок. Так `TextSink` печатает событие
дословно и остаётся побайтово совместимым с сегодняшним выводом — существующие
тесты `cli` и есть его спецификация. Полноэкранный режим по `Kind` и `Speaker`
рисует метку и разделитель, а `Text` показывает как есть.

Справочные экраны (`help`, `facts`, `state`, `clocks`, `survey`) остаются одним
блоком под `EventSystem`: разбирать их на события незачем, они и так читаются
целиком.

Сессия перестаёт писать в `io.Writer` напрямую и пишет в `Sink`. Поле `Out`
остаётся конструктором `TextSink`, чтобы `NewSession(g, in, out)` продолжал
работать как раньше.

## 4. Экран

```
┌─ Гавань · Пристань ──────────────────── ход 3 · $0.06 ─┐
│ Мастер                                                 │
│   Дождь бьёт по доскам, вода стекает к самому краю…    │
│ ─────────────────────────────────────────────────────  │
│ Берн, стражник                                         │
│   — Добрый день. Чем помочь?                           │
│ ─────────────────────────────────────────────────────  │
│ Вы                                                     │
│   есть ли какие-нибудь слухи?                          │
├────────────────────────────────────────────────────────┤
│ ›  что за история с ночной сменой?▌                    │
└─ ↑↓ история · PgUp/PgDn прокрутка · Tab отладка · ^C ──┘
```

Три полосы: шапка (дело, место, ход, расход), транскрипт, строка ввода с
подвалом-подсказкой. Разделитель ставится между сменами говорящего, а не после
каждой строки: разделитель на каждой строке — это шум, из которого не видно
границ реплики.

Клавиши:

| Клавиша | Что делает |
|---|---|
| `←` `→` `Home` `End` `Ctrl-A` `Ctrl-E` `Ctrl-W` `Ctrl-U` | каретка и правка строки |
| `↑` `↓` | история ввода: ранее введённые фразы |
| `PgUp` `PgDn` `Ctrl-B` `Ctrl-F` | прокрутка транскрипта |
| `Tab` | переключение на панель отладки и обратно |
| `Enter` | отправить ввод |
| `Ctrl-C` | выход |

Прокрутка и правка строки не делят ни одной клавиши: `Ctrl-U` стирает строку до
каретки и ничего не прокручивает. Фокус всегда на вводе — отдельного режима
«фокус в транскрипте» нет, потому что переключать его пришлось бы вручную, а
играют в этом окне, а не читают.

История ввода — своё кольцо на стороне игры: у поля ввода библиотеки её нет.
Пустой ввод в историю не попадает, повтор подряд не дублируется.

## 5. Ход не морозит экран

Вызовы моделей идут секундами, а иногда десятками секунд. Поэтому `Feed`
исполняется не в цикле отрисовки, а в отдельной горутине, и события приходят в
интерфейс по каналу — реплики появляются по мере готовности, а не пачкой в
конце. Пока ход идёт, внизу крутится индикатор, а ввод заблокирован: два хода
одновременно ядро не переживёт, и «пока не ответили — не спрашивай» честнее,
чем очередь из фраз, ответы на которые перепутаются.

`Ctrl-C` во время хода прекращает игру, а не ход: отменять уже оплаченный вызов
модели незачем, а обрывать ход на середине — это состояние, из которого игра не
восстановится.

## 6. Панель отладки

Дамп обмена с моделью сегодня печатается в stderr, и в полноэкранном режиме он
затирает экран. Шлюз пишет в `io.Writer`, поэтому переезд простой: в
полноэкранном режиме `-debug-llm` направляется в кольцевой буфер в памяти, а
панель по `Tab` показывает его со своей прокруткой. Содержимое дампа не
меняется — это тот же текст, что летит в stderr сейчас.

Буфер кольцевой и ограниченный: одна сессия с `-debug-llm` даёт мегабайты, и
держать их целиком в памяти ради прокрутки незачем. Потолок — по числу записей,
а вытесненное считается («сброшено N записей»), чтобы обрезка не выглядела как
пропажа.

## 7. Пакеты и зависимости

Новый пакет `tui/` — над `cli`, как `actor` и `master` над доменом. `cli` о нём
не знает и не импортирует: полноэкранный режим необязателен ровно так же, как
модели.

Прямые зависимости: `charmbracelet/bubbletea` (цикл и ввод),
`charmbracelet/bubbles` (поле ввода и прокручиваемая панель),
`charmbracelet/lipgloss` (рамки и отступы). Это первые прямые зависимости
проекта; сегодняшние в `go.mod` пришли транзитивно с SDK.

Выбор объяснён так. Прокрутка с переносами, широкие символы, resize и
перерисовка без мигания — ровно та мелкая логика, где библиотека окупается:
своя реализация это 400–600 строк, которые тяжело покрыть тестами и легко
сломать на первом же емодзи. Цена — инверсия цикла, но она нужна и для своей
реализации тоже.

## 8. Флаг и режим по умолчанию

Полноэкранный режим включается сам, когда stdin И stdout — терминал, и не
включается иначе. Флаг `-plain` заставляет построчный режим на терминале: он
нужен для сравнения выводов и для тех, кто ведёт лог.

Не-терминал (пайп, `-script`, тесты, CI) полноэкранным режимом не становится
никогда: это и есть гарантия, что воспроизводимость не зависит от того, как
запущена игра.

## 9. Что НЕ делается

Мышь, поиск по транскрипту, темы и палитры, копирование в буфер, вкладки на
несколько дел, сохранение транскрипта из интерфейса. Прокрутку, выделение и
копирование до сих пор делает сам терминал; в полноэкранном режиме часть этого
теряется — и это цена, которую дизайн принимает сознательно, а не дефект.

## 10. Что проверяется тестами

- `Feed` исполняет ход и возвращает признак конца — на нём переписываются
  существующие тесты REPL, и они остаются зелёными без правок смысла.
- `TextSink` печатает события ровно так, как печатается сегодня: тесты `cli`
  и есть спецификация формата.
- Сборка событий: реплика NPC приходит с именем говорящего, речь игрока —
  с меткой «Вы», отказ приходит `EventRefusal`, а не текстом с префиксом.
- Обвинение как автомат: четыре последовательных `Feed` заполняют четыре слота,
  пустой слот прекращает набор, а не вешает сессию.
- Кольцо истории ввода: порядок, отсутствие пустых и повторов подряд.
- Кольцевой буфер отладки: потолок, счётчик вытесненного.

Не проверяется автотестами и смотрится глазами: сама отрисовка, поведение при
resize, мигание. Живой прогон «Гавани» — приёмка.

## 11. Риски

- **Инверсия цикла заденет больше, чем кажется.** 44 места печати в `cli` уходят
  в события; ошибка в любом ломает формат, который сегодня проверяют тесты. Это
  и есть страховка: тесты падают сразу.
- **Обвинение.** Автомат вместо вложенного цикла — единственное место, где
  меняется логика, а не обёртка. Требует своих тестов до переезда.
- **Первые прямые зависимости.** Сборка перестаёт быть чисто стандартной.
  Смягчение: TUI необязателен, и без него игра работает целиком.
