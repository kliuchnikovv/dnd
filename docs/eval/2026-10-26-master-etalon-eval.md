# Эвал ИИ-мастера по Эталону — как запускать

**Дата:** 2026-10-26
**Статус:** рабочий инструмент (harness собран, живой прогон ждёт живого ключа)
**Основание:** [`docs/design/2026-09-02-master-reference-standard.md`](../design/2026-09-02-master-reference-standard.md) — Эталон Мастера
**Связано:** ADR-0007 (Эталон — главный критерий качества MVP), ADR-0008 (трёхролевая анти-утечка), `docs/eval/2026-09-05-injection-battery.md` (корпус инъекций)

## Что это

Инструмент, который гонит ИИ-Мастера по ходам золотой катки «Тихий Дол» и
оценивает **каждый ход по всем 13 пунктам рубрики A–D**. На выходе — отчёт,
где по каждому пункту видно pass / fail / «не применимо» / «не оценено», и по
каждому провалу — причина.

Эталон требует этого прямо (§«Эвал ИИ-мастера»):

> 1. **Золотой прогон как вход.** Прогнать ИИ-мастера по ходам катки «Тихий
>    Дол» (те же заявки игрока) и оценить каждый ход по применимым пунктам
>    A–D. Человек-Мастер здесь — верхняя планка.

## Где что лежит

| Что | Где |
|---|---|
| Рубрика: 13 пунктов, записи ходов, auto- и LLM-судьи | `eval/rubric/` |
| Золотой прогон «Тихий Дол» как данные (9 ходов) | `eval/rubric/golden.go` |
| CLI: прогон, отчёт, JSONL | `cmd/eval/` |
| Загрузка `.env` (общая для всех бинарников) | `dotenv/` |

## Запуск

```bash
# 1. Посмотреть сценарий без модели (что именно проверяем, что применимо).
go run ./cmd/eval -dry

# 2. Проверить, что конвейер живой (без ключа, без денег).
go run ./cmd/eval -stub

# 3. Живой прогон.
go run ./cmd/eval \
  -model anthropic/claude-sonnet-5 \
  -price-in 2 -price-out 10 \
  -out runs/eval.jsonl
```

Ключ провайдера — в `.env`:

```
export OPENROUTER_API_KEY=sk-or-v1-...
```

Файл читает **сам бинарник**, а не шелл: `source .env` задаёт переменную
оболочки, а не окружения, и дочерний процесс её не видит. Уже заданное
окружение перебивает файл — поэтому `MODEL=... go run ./cmd/eval` работает
без правки `.env`.

## Флаги

| Флаг | Смысл |
|---|---|
| `-env` | путь к `.env` (по умолчанию `.env`) |
| `-model` | модель (иначе `MODEL` из окружения) |
| `-provider` | `openrouter` \| `anthropic` (иначе `PROVIDER`, иначе openrouter) |
| `-price-in` / `-price-out` | цена, $/млн токенов (иначе `PRICE_IN`/`PRICE_OUT`, иначе таблица `llm/pricing.go`) |
| `-turns N` | прогнать первые N ходов (быстрый смоук) |
| `-guard` | `off` (по умолчанию) \| `check` \| `enforce` — см. ниже |
| `-out` | файл JSONL с полными вердиктами |
| `-quiet` | отчёт без проз (только сводка и провалы) |
| `-dry` | без модели: сценарий + применимость пунктов |
| `-stub` | без модели и без денег: весь конвейер на `llm.Fake` |

## Методика: что именно измеряется

### Оценивается Мастер, а не движок

Золотой прогон — это **данные**: заявка игрока, механический исход, что
открылось, что бросил мир. Механика из человеческой катки берётся как
референс (те же кости, тот же исход), а прозу пишет ИИ-Мастер заново. Так
две модели сравнимы: один и тот же вход, разница только в речи.

Движок при этом не пересчитывается — это зона его собственных тестов.

### Рубрика оценивает СЫРУЮ прозу Мастера

Страж выключен по умолчанию (`-guard=off`). Причина: D13 — «Мастер знает
секрет и дозирует его» — это про Мастера. Если гард спрячет утечку, метрика
померкнет, и мы перестанем знать, держит ли Мастер середину.

`-guard=check` — страж проверяет сырую прозу и печатает свой вердикт
отдельной строкой («утечка: …» / «ok»). Это ответ на вопрос «а в проде починил
бы?», не влияющий на оценку.

`-guard=enforce` — проза идёт через страж, и оценивается уже
отредактированная (как в проде). Для CI-гейта это режим «что увидит игрок».

### Три состояния, а не два

В отчёте знак `–` означает «пункт неприменим к этому ходу» (не было броска →
A2/A3/A4 не о чем судить). Знак `?` означает «применим, но НЕ ОЦЕНЁН» — нет
LLM-судьи или модель ответила неразборчиво. Это **пробел**, и он виден
отдельно, в разделе «Пробелы оценки».

Пока пробелы не закрыты, этал неполон: нельзя сказать «Мастер прошёл
рубрику», если половина пунктов не смотрели.

### Стоимость одного прогона

На ход: 1 вызов Мастера + 9 вызовов LLM-судьи (по одному на мягкий пункт) +
1 вызов стража (если включён). Мягкие пункты считаются **параллельно** —
та же цена, в разы меньше ожидания.

На всю катку (9 ходов) при `anthropic/claude-sonnet-5`: порядка $0.3–0.5.
Потолок `CAP_TURN` по умолчанию 16 (1 + 9 + 1 + запас).

## Что покрыто автоматически, а что — моделью

| Пункт | Исполнитель | Сигнал |
|---|---|---|
| A2.a | auto | маркер броска (`d20/бросок/кость`) или формат `число+число` в прозе |
| A2.b | auto | на нат-20 «чисто/блестяще»; на сильном провале «мимо/провал/кровь» |
| A3 | auto | «DC N» / «против N» / «легко/норма/трудно» |
| A4.a | auto | на полном провале: раскрытое/бит/развязка ИЛИ движение в прозе |
| A4.b | auto | на частичном успехе: cost-words (рана/потеря/ценой/расход) |
| C10 | auto | бросок мира виден игроку (`d20=N` / «оно:») |
| D13 | auto | фраза из ключ-ответа сцены не появилась в прозе до заслуги |
| A1, B5, B6, B7, C8, C9, C11, C12 | LLM | якорь Эталона в системном промпте, ответ — строгий JSON |

Ограничение auto-судьёв: D13 ловит дословные утечки, но не пересказ своими
словами. LLM-судья в этот пункт намеренно НЕ входит — иначе он увидит
ключ-ответ и потеряет смысл.

## Чего нет (и почему это не страшно)

- **Runner под dnd5e/дедукцию.** Harness работает на золотом прогоне и на
  сценах `vignette/`. Собственный runner под `core/scenarios/deduction`
  (собственная state-машина) — отдельная работа.
- **C12 на одном ходу.** «У сессии есть арка» — свойство всей серии; на
  одиночном ходу честно NA, а не «pass».
- **Негативные эталоны** (тряпка/вахтёр как контрольные провалы). Часть
  покрыта тестами harness'а (`TestGoldenCatchesCloth`, `TestGoldenD13LeakDetection`),
  но отдельный корпус «плохих Мастеров» не собран.

## Расхождения с Эталоном, найденные при переносе (27.10.2026)

Первая версия `golden.go` разошлась с документом в четырёх местах. Исправлено
все; здесь — зафиксировано, чтобы правка не вернулась.

| Ход | Было в коде | В Эталоне | Последствие |
|---|---|---|---|
| 4 | «не вышло», 12 против 18, маржа −6 | **Успех** = сет-пис, порог Трудно 18 | A4 на ходе 4 оценивался вместо NA; сет-пис терялся |
| 4 | бросок мира отсутствовал | `(оно: 5)` | C10 на ходе 4 не оценивался вовсе |
| 5 | «12−2 = 10 против 18 — мимо на 4», маржа в полях −4 | «Бросок −4», «вышло, **но** с ценой» | арифметика не сходилась (10−18 = −8) и противоречила «вышло» |
| 6 | нат-1 с итогом 1 | «Нат-1 (5/14)» — итог **5** | потерян модификатор +4 (edge + тег) |

Плюс два расхождения в модели, а не в данных:

- **A2 на ходе 1.** Эталон тагует A2 на старте («бросаю в терминале» — доверие
  к кости), а модель считала A2 применимым только при броске. Теперь у хода
  есть флаг `DieTalk`: если Мастер говорит о кости, A2 применим и проверяет,
  что кость показана.
- **п.9 «вся математика на виду».** В строке броска модификаторы были
  спрятаны (`d20=19+0`), хотя Эталон требует `19 +edge2 −4 +2`. Теперь видны.

Защита от повтора: тест `TestGoldenArithmeticConsistent` требует
`total = d20 + mod` и `margin = total − dc` на каждом ходе. Ошибка вида
«10 против 18 с маржой −4» такой тест ловит.

### Что осталось неоднозначным в самом документе

Эталон задаёт не все числа явно. Правила разбора зафиксированы в комментарии
к `GoldenRun()`:

- п.4: d20 не указан → взят 16 при +2, итого ровно порог 18 (успех);
- п.6: «(5/14)» — это итог против порога, значит на нат-1 модификатор +4;
- п.8: итог игрока не указан → взят как на п.6 (тот же +4 тега);
- п.3 и п.7: итоги взяты как показаны, разбивка по модификаторам — только там,
  где документ её приводит.

Если решение по этим числам будет другое — правятся данные в `golden.go` и
тест `TestGoldenRunShape`; на вердикты рубрики это влияет только через
маржу.

## Теги Эталона как нижняя планка

Скобки в документе («какие пункты чек-листа сработали») вынесены в данные как
`EtalonTags`. Отчёт сравнивает их с фактическими вердиктами ИИ-Мастера и
показывает блок **«Нижняя планка (человек-Мастер vs ИИ)»** — что человек
вытянул, а ИИ нет.

Это не «сколько ИИ набирает», а «держит ли ИИ человеческую линию». Если ИИ
вытянул больше — это не gap, это хорошо.

## Статус живого прогона

Конвейер собран и проверен на стенде (`-stub`): шлюз → роли → Мастер →
рубрика → отчёт → JSONL, 9 ходов, все вердикты на месте.

Живой прогон по «Тихому Долу» **не выполнен**: ключ `OPENROUTER_API_KEY` в
`.env` отвергнут провайдером (`401 User not found` — формат ключа верный,
`/models` читается, аккаунт за ключом удалён или отозван). Ошибка в CLI
переводится в actionable-сообщение, а не в сырой JSON.

Чтобы закрыть прогон: заменить ключ в `.env` и выполнить команду из раздела
«Запуск» → п.3. Больше ничего менять не нужно.
