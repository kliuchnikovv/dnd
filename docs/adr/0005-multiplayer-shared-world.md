# ADR-0005: Мультиплеер — асинхронный общий мир и барьер между пати

**Статус:** Предложен
**Дата:** 2026-08-21
**Решает:** Валерий Ключников
**Связано:** `docs/adr/0001-layered-world-trusted-core.md` (слои, воркер, снепшот),
`docs/adr/0002-action-log-write-ahead.md` (события, single-writer),
`docs/adr/0003-threat-model-free-dialogue.md` (недоверенный контент),
`store/future.go` (`Case` verdict/truth, `WorldEvent`, `Region`, `PartyID`)

## Контекст

Вижен — MMO-составляющая: действия одних игроков влияют на мир. Нужны оба
«коопа» — играть вместе в одно окно и играть «по часам» (ход в окно пары часов,
потом переходит). И нужно, чтобы мультиплеер **не открыл вектор инъекции/
газлайтинга** между игроками (ADR-0003) — при этом мир ощущался общим.

## Решение

**Асинхронный общий мир, синхронизируемый событиями.** Пати играют параллельно
против общего персистентного мира; исходы расходятся рябью через воркер мира.
Это то, подо что построены слои ADR-0001 (мир медленный общий, окружение —
проекция, сессия — живая).

**Оба коопа — один механизм, окно хода как политика.** Сессия — мультиакторная,
с очередью ходов; ход = закоммиченное событие (WAL). «Вместе» и «по часам» —
это два пресета одной ручки: длина окна хода + ожидание присутствия + политика
отсутствия. Отдельного «реалтайм-движка» нет: ядро пошаговое, журнал событийный,
каденс — параметр.

**Партия — единица, и она уже в коде.** `party_knowledge`, досье per-party,
`PartyID` ключуют всё партией. Одиночная игра — партия из одного. Кооп — населить
партию несколькими актёрами + очередь ходов + политика каденса. Не новый мир —
заполнение готовой абстракции.

**Два уровня состояния — один журнал в разных областях.** Внутри сессии
(кооп): состояние живое и общее, сериализовано очередью ходов (единственный
писатель — ядро). Сессия ↔ мир: сессия на снепшоте мира, исходы уходят
событиями; снепшот изолирует **сессию от мира**, не участников друг от друга.

**Воркер мира — единственный писатель.** Сессии *предлагают* события, воркер
применяет по порядку (event-sourcing из ADR-0002). Гонок нет — писатель один;
конфликты общих фактов (кто опроверг дело, кто взял награду) решает политика
воркера. Правда изолирована по делу; наружу идёт только `verdict` (раскол
verdict/truth уже в `future.go`).

**Барьер между пати (стержневое ограничение).** Межпартийное влияние —
**только через структурный канон мира, никогда напрямую.** Пати видит
*результаты* чужой игры (сожжённая деревня, спасённый торговец, изменённая
репутация фигуры), но не стычки, не обмен, не записки. Через границу пати
проходит **закрытый типизированный набор фактов/событий авторства системы**, а
`Мастер` пересказывает их **своим доверенным промптом**. Сырой ввод игрока
заперт в его собственной сессии и в чужой контекст не попадает никогда.

## Почему барьер — это и безопасность, и продукт

**Безопасность:** вектор инъекции/газлайтинга через сохранённый чужой контент
**схлопывается** — enum и id инъекцию не несут, а свободного текста через границу
нет. Остаётся один тонкий канал — именная атрибуция (имя героя пати A всплывает у
пати B): структурный id + модерируемое имя, маленькая поверхность для
классификатора. Не хочешь и его — атрибуция абстрактна («какие-то странники»).

**Продукт:** это не жертва, а идентичность — **мир общих последствий, а не общего
присутствия.** Мир помнит деяния всех, но игрока напрямую не встречаешь. Чище как
фантазия (нет токсик-PvP и спама), уникально на рынке, и безопасно строить. Цена:
нет прямого PvP, торговли, кросс-парти коопа.

## Модель доверия держится

Каждый ход, кто бы из партии его ни подал, идёт через доверенное ядро — оно
валидирует независимо. Правда изолирована, никто из партии её не видит. Кооп
**не добавляет риска целостности канона** — только социальные риски (стоп хода,
гриф своих), а их лечит политика каденса + модерация, не правки ядра.

## Рассмотренные варианты

### A: async-общий-мир + барьер через структурный канон (принимается)

| Измерение | Оценка |
|---|---|
| Ощущение общего мира | Высокое: последствия всех видны |
| Безопасность | Высокая: межпартийный free-text-вектор устранён |
| Сложность | Средняя: воркер, события, каденс-политики |
| Готовность кода | Высокая: партия/verdict/outbox уже заложены |

**За:** вижен без синхронного присутствия; главный риск снят барьером.
**Против:** нет прямого взаимодействия игроков — сознательный размен.

### B: прямое взаимодействие пати (PvP/торговля/кросс-кооп)

**За:** «настоящий» MMO-контакт. **Против:** возвращает free-text-вектор
инъекции/газлайтинга и гриферство в полный рост; конфликты взаимодействия надо
мирить. Отклонён при приоритете изоляции.

### C: только одиночная игра, без общего мира

**За:** просто и безопасно. **Против:** убивает MMO-вижен. Отклонён.

## Степень общности (сабрешение, эволюция)

**Инстансы-с-рябью** (пати — параллельные инстансы, связаны слоем канона) →
**региональные шарды** (`Region` уже заведён) → **глобальный мир**. Вижен
выполняется уже инстансами-с-рябью; глобал — позже.

## Порядок к MVP

1. **Async общий мир** — партии из одного, рябь событиями через воркер. Сердце
   вижена без сессионной синхронизации.
2. **Long-turn кооп** — проще live: нет латентности и присутствия,
   Words-With-Friends-каденс, ложится на мобилу и пуши.
3. **Live кооп** — лобби, присутствие, быстрый цикл.

## Последствия

- **Проще:** барьер снимает межпартийную безопасность и конфликты взаимодействия;
  оба коопа — пресеты одного механизма; партия/verdict/outbox переиспользуются.
- **Сложнее:** воркер мира и протокол событий; очередь ходов + владение +
  каденс/таймаут; пуш на передачу хода; классификатор на тонком канале имён.
- **Пересмотреть:** политику конфликтов общих фактов; время жизни снепшота
  (per-case vs рефреш); шардирование по регионам под нагрузкой.

1. [ ] **Барьер пати** как инвариант: ничто, сочинённое игроком свободным
       текстом, не читается в контекст другой пати; через границу — только
       закрытый типизированный набор фактов мира. Тест стережёт, как изоляцию `truth`.
2. [ ] **Воркер мира** на `outbox`/`world_events`: single-writer, порядок,
       политика конфликтов общих фактов; раскол verdict/truth.
3. [ ] **Мультиактор-сессия:** участники + очередь ходов + `actor_id` в журнале;
       нарратор адресует партию.
4. [ ] **Каденс-политики:** окно хода, присутствие, таймаут → скип / ИИ-напарник /
       держим; пресеты «live» и «long-turn».
5. [ ] **Пуш на передачу хода** (транспорт ADR-0004).
6. [ ] **Именная атрибуция** через классификатор (модерируемое имя героя) —
       опционально; дефолт — абстрактная атрибуция.
7. [ ] **Проекция окружения** из общего канона мира на пати (следом за снепшотом
       из ADR-0001).
