# ADR-0010: view-ось правила — плюральна через реестр

**Статус:** Принят
**Дата:** 2026-09-09
**Решает:** Валерий Ключников
**Связано:** достраивает ADR-0006 (две оси пластичности) по view-оси; фундамент
для dnd5e-мер (спека `../handoff/2026-09-09-spec-2-dnd5e-view-conformance.md`) и
киберпанк-рулсета (спека `../handoff/2026-09-09-spec-3-cyberpunk-red-ruleset.md`);
механику M1a (ADR-0009) не трогает.

## Контекст

Аудит швов перед добавлением новой системы правил вскрыл асимметрию. **Механическая
ось плюральна:** `core.RegisterRuleset`/`LookupRuleset`, кость `core.Dice` свободна,
глаголы расширяются через `ExtraVerbs()`, лист персонажа непрозрачен ядру (каждая
система парсит сама). А **view-ось — нет.** Интерфейс `view.Ruleset` («правило само
называет свои меры: раны, grit, часы, heat») существует, но:

- единственная реализация — `cli.RefRuleset{}` (ось «Порог»);
- у dnd5e своих мер нет (здоровье обходится objective-панелью из ядра, заплатка на
  архетипе adventure);
- сервер и CLI **хардкодили** `serverRuleset = cli.RefRuleset{}` и
  `RefRuleset{}.Meters(g)`;
- реестра `RulesetKind → view.Ruleset` не было.

Итог: механику меняешь честно, а меры на экране у **любой** системы — Порога.
Расширение новыми правилами видно в резолюции, но не на экране.

## Рассмотренные варианты

- **A. Реестр view-правил** (по образцу механической оси). Принят.
- **B. Оставить хардкод, каждой системе — свой путь в сервере/CLI ad hoc.** Отклонён:
  не масштабируется, каждый новый рулсет правит turn-путь сервера вслепую.
- **C. Влить меры в `core.RuleSystem`.** Отклонён: `view/` обязан оставаться
  свободным от слов конкретного правила; меры — презентация, не механика.

## Решение — реестр view-правил

1. **Реестр.** `view.RegisterRuleset(core.RulesetKind, func() view.Ruleset)` +
   `LookupRuleset(kind) (view.Ruleset, bool)` — зеркало `core.RegisterRuleset`.
   Реестр держит ТОЛЬКО значения интерфейса `view.Ruleset`; слов конкретного
   правила (`grit`, `Humanity`) `view/` не знает — они в реализациях, регистрируемых
   side-effect'ом импорта пакета правила.
2. **Порог регистрируется.** `cli.RefRuleset{}` → `RegisterRuleset(RulesetThreshold, …)`
   в `init`.
3. **Сервер берёт правило сессии.** Глобальный `serverRuleset`-хардкод снят;
   `sessionRuntime.viewRuleset` резолвится из `RulesetKind` сессии при создании
   (`resolveViewRuleset`), `view.Build` получает его. То же для CLI
   (`cli/render.go` через `resolveRuleset`) — прямых ссылок на `RefRuleset{}` в
   turn-пути не осталось.
4. **Фолбэк.** Неизвестный/незарегистрированный kind → Порог + `log.Printf`
   предупреждение (обратная совместимость дел без `rules`).

## Последствия

- Каждая система правил показывает СВОИ меры; dnd5e (спека 2) и киберпанк с
  Humanity/Heat (спека 3) объявляют их сами через тот же реестр.
- **M1a (`rules/threshold`) байт-в-байт нетронут** (ADR-0009) — меняется только
  КАК выбирается view-правило; `git diff -- rules/threshold` пуст.
- Порог ходит через реестр к тому же `RefRuleset` — поведение не изменилось,
  прежние view-тесты зелёные.
- Третья ось пластичности — создание персонажа — идёт тем же паттерном реестра
  (спека `../superpowers/…`/проектный `spec-character-creation`): `CharacterBuilder`
  на рулсет, сервер собирает лист авторитетно.
