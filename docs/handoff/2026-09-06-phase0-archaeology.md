## 0. TL;DR — главное расхождение (escalation)

Спек исходит из посылки: «ядро СТРУКТУРНО богаче прототипа и во многом уже правильное; задача —
доработать, а не переписать». Для **анти-утечки (§1, Ф1)** это верно и подтвердилось: truth-isolation
в ядре уже реализована глубоко и по-взрослому (Мастер физически не получает `Truth` — см. §1 ниже).

Но для **механик D&D (§2, items 3/5/6/7/9/10/11/16)** посылка не выдерживает: **текущее ядро — это
M1a, детективно-дедукционный «измерительный» движок** (факты `FactHolder`/`Gate`, `Knowledge` с
confidence/корроборацией, `Clocks`, боевые `Encounter`, сценарии `deduction`/`adventure`), а прототип
проверял **совсем другой движок — хоррор-виньетку** (объект/аспект/тир с bandwidth-от-маржи, пассивные
tells `10+Edge`, hazard-глубина, режимы traverse/disable/hold, беаты). Это два разных набора правил на
разной доменной модели.

Как следствие, по мех-половине §2 «доработкой» закрываются лишь честная кость (§2.1) и, косвенно,
лок-на-успехе (§2.4). Остальное — **net-new или конфликт**, причём часть (DC-шкала §2.5, нат-1 §2.9,
adv/dis §2.6) при «ретрофите в `rules/threshold`» **перетюнит живой инструмент M1a** (изменит DC и
распределение исходов во ВСЕХ существующих кейсах и distribution-тестах). Память проекта: *M1a —
измерительный инструмент, его гейт упирается в живых людей* — то есть менять его тюнинг на середине
измерения нельзя молча.

**Развилка, которую нужно подтвердить у автора спека (блокирует Ф2, НЕ блокирует Ф1):**

- **Вариант A (изоляция, рекоменд.):** проверенные правила прото ложатся в **новую rule-систему**
  (напр. `rules/vignette`) + **новый scenario-архетип** рядом с `deduction`/`adventure`, за швами
  ADR-0006 (правило × сценарий). Пассив/hazard/bandwidth/traverse-hold/нат-1-по-марже/adv-dis живут
  ТАМ; `rules/threshold` (M1a) не трогаем — инструмент цел. Генератор и корпус инъекций гоняются против
  vignette-движка. Минус: два рулсета сосуществуют (но ADR-0006 ровно про это).
- **Вариант B (ретрофит в ядро):** правила прото вносятся прямо в `rules/threshold` + существующие
  сценарии (как буквально читается Ф2 спека и таблица §4). Плюс: один рулсет. Минус: перетюн M1a —
  DC 5/10/15/20/25/30 вместо 10/14/18, снятие нат-1-ступени, adv/dis 2d20 меняют исходы во всех кейсах;
  distribution-тесты и калибровка M1a переписываются. Для «живого» M1a это регресс инструмента.

Моя рекомендация — **A**: сохраняет и решения прото, и M1a, и прямо ложится на ADR-0006/0007.
Таблица §2 ниже размечена нейтрально (что есть / чего нет), план в последней колонке дан **для варианта A**;
если выберем B — план тот же по сути, но правки идут в `rules/threshold`/существующие сценарии и тянут
переписывание distribution-тестов.

## 1. Ф1 (truth-isolation) — статус: по сути ГОТОВО, дореза минимальна

Разворот п.2 ADR-0007 в коде **уже соблюдён конструкцией**:

- Мастер получает `master.World{Setting, Scene, Speaker}` (`master/master.go:56-60`) — **поля `Truth`/
  скрытых тиров НЕТ**. `Speaker` (`master/master.go:82-110`) прямо документирован «правды дела здесь нет».
- `Narrate(...)` (`master/master.go:475`) на вход: `frame` (авторский флейвор), `World`, `outcome`
  (мех-строки ядра), `state` (дайджест для гварда). Секрета ни в одном.
- Бэкстопы: `accusation.Truth` несериализуема (`String()→<redacted>`, `MarshalJSON` — ошибка,
  `core/scenarios/deduction/accusation/truth.go:15-25`); `core.SceneView` не несёт граф фактов/правду
  (`core/scene.go:9-11`); read-scope реестр запрещает truth-скоуп нарратору
  (`llm/capability.go:16-18,87-92`).
- Колл-сайты кладут в `World` только видимое: `cmd/dnd/main.go:525-527`, `server/prose.go:126-127`,
  `actor/actor.go:1180-1181`.

**Действия Ф1 (маленькие):** (1) написать **регресс-ассерт-тест** «Мастер не получает Truth» — прогнать
контекст нарратора и проверить, что ни `World`, ни `outcome`, ни `state` не содержат строку правды/
незакрытых holder-фактов; (2) оформить **ADR-0008** (`docs/adr/0008-*.md`) «трёхролевая анти-утечка:
ядро владеет правдой, Мастер её не получает, страж-редактор» — заменяет п.2 ADR-0007. Это можно делать
сразу, оно не зависит от развилки §0.

## 3. §7 — открытые вопросы, решения Ф0

- **Q1. Consistency-guard vs leak-editor — один хук или два?** В ядре СЕЙЧАС это **один** `guard.Guard` с
  двумя векторами (leak `invented` + contradiction `contradicts_state`), включён по умолчанию
  (`GUARD_LINES` default true `cmd/server/narrator.go:64`), НЕ off. Спек считал их разными и leak-editor
  держащим `Truth`. **Решение:** оставить один интерфейс `Checker`, но **две конфигурации-режима**
  (leak-режим держит защищённые факты; consistency-режим — дайджест). Отдельный тип плодить не надо;
  добавить `ended`-карваут. (Совпадает с предпочтением спека «скорее два» — по ЗАДАЧЕ два режима, по
  КОДУ один хук.)
- **Q2. Генератор — отдельный пакет?** Да — **`scenegen/`** отдельным пакетом, пре-пассом до сессии
  (совпадает с предпочтением спека и с изоляцией знания генератора из DESIGN прото).
- **Q3. Где живёт «пассивный порог» тира?** Расширить holder/тир-модель полем `Passive int` (в
  vignette-рулсете/сценарии), НЕ плодить параллельную модель сцены. `store.Gate` уже есть — тир-порог
  ложится рядом с `Threshold`.
