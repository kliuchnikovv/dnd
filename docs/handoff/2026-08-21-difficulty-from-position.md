# Хендофф в разработку: Порог броска от позиции

**Статус:** готово к работе · не начато (проверено: `DifficultyFor`/`Opposed`/`Exposed` в коде нет)
**Дорожка:** серверное ядро (Go) · **Исполнитель:** локальный Claude Code · **Дата:** 2026-08-21

## Одно предложение

Для несудимого/импровизированного действия сложность ставит **ядро** функцией от
позиции (`Opposed` → к Трудно, `Exposed` → к Легко), а не рассказчик и не флат-Норма.
Авторский `gate.threshold` по-прежнему сильнее.

## Почему это, почему сейчас

Из живой катки: импровизированные действия («воткнуть стрелу в узел») получали
порог на глаз от мастера — прямое нарушение принципа ADR-0001 «рассказчик
бесправен над костью». Это последняя готовая спека, которую ещё не собрали, и она
разблокирует импровизацию из ADR-0003. Зависимости на месте: API мутаций,
капабилити, `SceneView` — уже на `main`.

## Definition of Done

- `SceneView` несёт `Opposed`/`Exposed`, выставляет их **ядро** из состояния,
  не текст модели.
- `DifficultyFor(intent, view)` в `rules/threshold`: авторский гейт сильнее;
  иначе база Норма, ступень к Трудно/Легко, не больше одной; чистая функция.
- `Resolve` берёт порог через `DifficultyFor`; поведение судимых гейтом действий
  не меняется (распределение исходов зелёное).
- Тест частоты порога (в духе теста факторов) ловит перекос.
- `go test ./...` зелёный; `e2e/architecture_test.go` не тронут (функция в
  `rules/threshold`, `core` её не импортирует).
